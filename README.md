# 开源课程 · FDE 模拟作业：拾光连锁「门店补货与库存协同」

这是一份 **FDE（Forward Deployed Engineer）九阶段流程**的课程模拟作业仓库。案例为合成场景「拾光连锁 · 货架满了，爆款却没了」，从角色访谈、现状还原一路做到四来源收敛与证据核对。

仓库当前覆盖 **阶段 01 业务挖掘** 与 **阶段 02 现场调研**；阶段 03 及之后的模拟项目代码将放入 [`src/`](src/README.md)。

> 本仓库所有人物、门店、金额、指标均为**合成训练数据**，不代表任何真实企业的授权、业务执行或客户验收。这一点在每份交付文档的开头都做了声明。

## 证据与标注约定

读这些文档会看到大量 `f00`–`f55` 编号和 `retail-01～04`，原因很简单：作业的核对问题就是「**哪份记录能支持这个说法**」，所以每个判断都必须能回溯到具体证据编号。

| 标注 | 含义 |
|---|---|
| `f00`–`f55` | 访谈事实台账编号，出自 `docs/discovery-report.md` |
| `retail-01`～`04` | 四份可核对资料编号 |
| 【已证 fXX】 | 直接引自材料，可作结论 |
| 【原文·零售-0XX】 | 补录问答的原文增量点 |
| 【核对结论】 | 对材料做的比对与判定，可复核 |
| 【待核实】 | 材料未记录，写明向谁确认、拿什么算数 |
| 【建议】 | 本人判断，非材料内容 |

**标【待核实】的地方表示材料未记录，不代表事实不存在。** 这是本作业最容易出错的地方，也是几份文档反复强调「不越界推断」的原因。
