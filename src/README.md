# src · 模拟项目代码

本目录用于存放**阶段 03（需求定义）及之后**的模拟项目代码。当前为空。

## 为什么现在是空的

阶段 01 与阶段 02 的产出全部是文档：访谈记录、现状流程、证据核对。这些都是"先把事情看清"的动作，还没有进入需要写代码的环节。在证据不足的情况下先写代码，等于把未验证的假设固化成实现。

## 计划结构（占位，随阶段推进调整）

```
src/
├── data/        只读数据接入与字段校验
├── validate/    确定性校验：整箱取整、仓容上限、人工签核前置
├── agents/      智能体与工具边界
└── logs/        审核日志（要求可重建当次处理）
```

## 必须遵守的约束

以下不是设计偏好，而是案例中已被明确记录的约束，写代码前先对照：

1. **只读优先。** 供应商下单接口尚未审批（f32），首期只导历史 CSV，不写回业务系统。
2. **不得绕过人工签核。** 自动补货建议转成实际下单前必须有人工签核（f44、f45）。
3. **关键原因必须是结构化字段。** 现状是"没有作为结构化字段随业务交接"（f14），这是时效不可测的直接原因。
4. **接口失败要降级而不是中断。** 继续原人工流程，保留只读快照与时间戳，恢复后按业务编号去重补齐（f35）。
5. **不记录口令与非必要个人信息。** 审核日志只保留可重建当次处理所需的版本、建议内容、人工修正与签核人（f45）。
6. **历史快照不得伪装成当前状态。** 超过一个周期的结果要标注待刷新（f34）。
