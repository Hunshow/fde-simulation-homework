## 在线需求分析
现有事实显示，问题并非单纯“预测不准”：门店账实差异约8%、货在后仓但货架未补、系统仍算有库存（retail-f10、retail-f12）；销量为零可能是缺货截断（retail-f31）；约30%延迟补货源于配送排队而非预测（retail-f51）；补货还受最小起订量、整箱规格与仓容上限约束（retail-f20）。因此最值得先做的切入点是“可售库存与缺货标识治理+人工复核闭环”，而非直接自动补货下单。试点边界已明确为8家门店、50个常温SKU、6周，先历史回放再并行（retail-f02、retail-f05），预算16万元封顶（retail-f03）。自动采购不能直接上线（retail-f22），兜底与审计要求已提出（retail-f44、retail-f45）。以下假设均待验证，调查覆盖率不代表验收通过。

## 需求如何归纳

先从已采集事实形成问题假设，再约定业务结果、范围、失败控制和验收。缺少的来源标记待补，不能把六人访谈完整率当作四来源收敛或需求确认。

### 业务流程拆解

要回答：问题发生在哪一步，为什么要这样划分智能体？

1. 先画人工现状泳道，写出触发、输入、8–15个处理步骤、交接和异常。
2. 区分判断点与执行点；按使用的数据、权限、模型能力与失败方式组合执行步骤。
3. 在不可逆动作前设置确定性校验；为低置信、缺资料、冲突和越权安排具名人工接收人。

交付链：现状流程 → 失败方式 → 智能体/工具边界 → 校验与人工升级路径

原文：frameworks/workflow-decomposition.md

### 业务结果与不可逆风险矩阵

要回答：多个需求中，先做哪个最小可验证方案？

1. 列出3–5个候选切入点，分别说明改善的业务结果、现状基线和投入。
2. 评估失败何时被谁看见、能否在损害前拦截、是否可以撤销；不要把模型置信度等同于业务风险。
3. 优先选择高价值、可拦截且可恢复的切入点；高风险需硬约束和责任人否决权，价值或风险未知先补证据。

交付链：候选方案 → 价值/风险比较 → 选择与暂缓理由 → 验收指标与停止条件

原文：frameworks/outcome-risk-matrix.md

### 四来源收敛

要回答：谁说要做，哪里真的坏了，范围允许什么，技术是否可行？

1. Buyer：核实业务目标、预算、优先级和决定权；Operator：用最近一单还原真实操作和失败位置。
2. Brief：核对书面目标、范围、时间和排除项；Industry：寻找可比技术实践，并核实本项目的数据与接口差异。
3. 检查四个视角是否指向同一瓶颈。分歧保留在问题清单：一线帮助定位故障，决策者确认价值，Brief约束范围，行业证据帮助判断可行性。

交付链：四视角陈述与来源 → 收敛/分歧 → 待核实问题 → 有边界的需求假设

原文：frameworks/4-source-convergence.md

### 从证据到候选需求

- REQ-1 先治理“可售库存与缺货标识”，再谈销量预测
  依据：retail-f10、retail-f12、retail-f31、retail-f33
  推导：店长称账实差异平均8%，且货在后仓而系统算有库存（retail-f10、retail-f12）；数据侧明确零销量可能是缺货截断（retail-f31）。若缺货标识不可信，预测输入即失真。但缺货标识由谁维护、更新频率尚未核实。
  判断：候选需求；需用结果与不可逆风险矩阵比较，P0/P1/P2不等于已完成价值风险评分。
  下一步：在8家门店、50个SKU中抽取20个重点SKU，连续5个工作日比对系统库存、货架可售量与缺货标识，计算差异分布；由秦芮确认字段可得性，林亦舟确认现场口径，顾明岚签字定基线。
- REQ-2 建立“建议量—整箱取整—仓容校验”人工复核单，暂不自动下单
  依据：retail-f20、retail-f22、retail-f15、retail-f23
  推导：补货受最小起订量、整箱规格和仓库分配上限约束，并非预测多少发多少（retail-f20）；计划员可调建议量，但跨店调拨需区域经理批准，自动采购不能直接上线（retail-f22）；每条辅助结果须显示原记录并经计划员核对（retail-f15）。复核单字段与审批颗粒度尚未确定。
  判断：候选需求；需用结果与不可逆风险矩阵比较，P0/P1/P2不等于已完成价值风险评分。
  下一步：用历史交接单样本回放一周，产出“建议量—整箱取整—仓容校验—未解决事项”模板；由唐映秋试用并记录人工修正次数，叶书确认分配口径，傅景确认不绕过签核。
- REQ-3 促销版本与门店改价回传缺口需先补齐，否则促销期预测不可用
  依据：retail-f11、retail-f21、retail-f44、retail-f24
  推导：促销临时变价会使预测失效，节假日客流差异大（retail-f11）；促销日历由运营维护，门店改价不总是回传（retail-f21）；临时促销等情形须停止自动建议并人工接手（retail-f44）。门店实际执行与下发版本是否一致尚未核实。
  判断：候选需求；需用结果与不可逆风险矩阵比较，P0/P1/P2不等于已完成价值风险评分。
  下一步：选取试点期内一次真实促销，追踪下发版本与门店实际售价的一致性；不一致时按兜底规则挂起并记录接手人，由傅景确认争议处理版本。
- REQ-4 配送排队与截单时间应先核查，避免把物流问题误判为预测问题
  依据：retail-f51、retail-f01、retail-f52
  推导：约30%延迟补货是配送排队，不是预测问题，需先核查仓库截单时间（retail-f51）；门店看不到分配依据（retail-f01）；需给门店看预计到货与本次未满足数量，且不改供应商合同（retail-f52）。截单时间现状与排队占比的统计口径尚未核实。
  判断：候选需求；需用结果与不可逆风险矩阵比较，P0/P1/P2不等于已完成价值风险评分。
  下一步：调取试点门店近4周配送记录，按截单时间、排队、仓容上限分类归因延迟；叶书确认分类口径，唐映秋核对未满足数量，形成门店可见的到货说明样例。
- REQ-5 以缺货、周转、报废三指标联合验收，促销期单列误差
  依据：retail-f42、retail-f02、retail-f53、retail-f00
  推导：验收须同时看缺货、周转、报废，促销期间单列误差（retail-f42）；缺货减少不能以全面增库存实现（retail-f02）；缺货率低于5%、周转35天、报废不增加的分母与排除规则须由业务负责人固定（retail-f53）。阈值基线与统计周期尚未核实。
  判断：候选需求；需用结果与不可逆风险矩阵比较，P0/P1/P2不等于已完成价值风险评分。
  下一步：由傅景与叶书书面固定三项指标的分母、周期与排除规则，秦芮确认数据可得；6周试点前3周回放、后3周并行，验收窗口切分由顾明岚签字。
- REQ-6 兜底、审计与人工签核作为试点硬门槛先行验证
  依据：retail-f44、retail-f45、retail-f35、retail-f34
  推导：临时促销、缺货截断、账实不一致、依据缺失或系统不可用时须停止自动建议并标明接手人与确认时间（retail-f44）；审核日志须能重建当次处理且不记口令（retail-f45）；接口失败时继续原人工流程并按业务编号去重（retail-f35）。这些是一票否决还是加权、日志查阅权限归谁批尚未核实。
  判断：候选需求；需用结果与不可逆风险矩阵比较，P0/P1/P2不等于已完成价值风险评分。
  下一步：在历史回放中人为注入一次接口失败与一次促销变价，检验是否触发兜底、日志能否重建；由傅景确认硬门槛判定方式，秦芮确认系统支撑能力。
